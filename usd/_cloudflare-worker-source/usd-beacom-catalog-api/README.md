# USD Beacom catalog API

## Provenance

This README and all source code in this Worker directory were initially
generated by OpenAI Codex on August 12, 2026, at the direction of the
repository owner. Robert Winslow has not independently verified them. The
implementation was based on live testing of the public SDBOR Banner
course-search interface. It is an independent, unofficial tool and is not
authored, reviewed, endorsed, or supported by SDBOR, USD, Ellucian, or
Cloudflare. Because the upstream interface may change, the generated code
should be reviewed and retested before it is reused or redeployed.

This Cloudflare Worker is a narrow CORS-enabled adapter for the anonymous,
public SDBOR Banner course-search application. It is not a general-purpose
proxy. Its deployed base URL is:

```text
https://usd-beacom-catalog-api.rmwinslow.workers.dev
```

The static frontend is `/usd/beacom-catalog.html` in the site repository.

## API routes

### `GET /api/terms`

Returns Banner's available-term lookup array without changing its JSON shape.

```text
GET https://usd-beacom-catalog-api.rmwinslow.workers.dev/api/terms
```

### `GET /api/semester?term=202680`

Returns the union of USD sections taught by everyone assigned to at least one
Beacom-subject section and every section physically scheduled in Beacom Hall.
The six-digit `term` parameter is required.

The Beacom seed subjects are:

```text
ACCT BADM BLAW DSCI ECON EMBA ENTR FIN HRM HSAD MGMT MKTG
```

On a cache miss, the Worker:

1. Starts an anonymous Banner session and selects the term.
2. Requests up to 500 USD sections in the seed subjects.
3. Deduplicates every `faculty[].bannerId` found in those sections.
4. Reselects the term to clear Banner's sticky subject filter while preserving
   the session-specific instructor IDs.
5. Requests up to 500 USD sections for those instructors with no subject
   filter.
6. Reselects the term again to clear Banner's sticky instructor filter.
7. Requests up to 500 USD sections with `txt_building=UB`, then unions those
   rows with the instructor result and deduplicates them by term and CRN.

If the seed has no instructor IDs, the seed itself is unioned with the Beacom
Hall query rather than issuing an unfiltered instructor query.

The response retains Banner's normal `success` and `data` fields. `totalCount`
is replaced with the number of deduplicated union rows actually returned. The
Worker also adds:

```json
{
  "limitExceeded": false
}
```

`limitExceeded` is `true` if the Beacom seed query, instructor-inclusion query,
or Beacom Hall query reports more than 500 sections. In that case the returned
course set can be incomplete. A total of exactly 500 does not set the flag;
the flag means Banner reported more than the requested 500-row page.

### `GET /api/instructor?term=202680&name=Carr`

Searches Banner's instructor lookup using the nonblank `name` string, then
returns up to 500 USD sections taught by every matching instructor in that
term. The Worker keeps the lookup IDs and course request in the same anonymous
session because Banner instructor IDs are session-specific. No subject filter
is applied to the course request.

The name is trimmed and may contain up to 100 characters. Banner controls the
matching behavior; it may return partial or fuzzy matches rather than only an
exact person-name match.

The response retains Banner's normal course-results fields and adds:

```json
{
  "limitExceeded": false,
  "instructorMatchCount": 3,
  "instructorLookupLimitExceeded": false
}
```

- `limitExceeded` is `true` when the matching instructors' course query
  reports more than 500 sections.
- `instructorMatchCount` is the number of distinct instructor IDs actually
  used in the course query.
- `instructorLookupLimitExceeded` is `true` when the name lookup returned more
  than 500 matches. Only the first 500 instructor matches are used, so the
  client should ask for a more specific name if this is true.

No instructor matches produce a normal successful empty result with
`totalCount: 0` and `data: []`.

Adding these properties does not break ordinary JSON parsing. JavaScript code
that reads only existing fields such as `payload.data` simply ignores unused
properties. A consumer would be affected only if it deliberately rejects
unknown fields with a strict schema validator.

## Client integration contract

For every selected term, the client can request `/api/semester`. If the
instructor field is nonblank, it can additionally request `/api/instructor`
with the same term and merge the two `data` arrays. The same section can occur
in both responses, so deduplicate by term plus `courseReferenceNumber` (CRN).
Treat any `limitExceeded` value, or `instructorLookupLimitExceeded`, as an
incomplete-results warning.

The client has named checkboxes for its principal Beacom subjects and an
`Other (EMBA, UHON, etc.)` checkbox. `Other` dynamically matches every returned
subject prefix that does not have a named checkbox; it is not a hardcoded list.

The Worker always applies `txt_campus=U`. It deliberately omits `txt_session`,
so USD sections in Vermillion, Sioux Falls, online, clinical, internship, and
other USD delivery/location categories remain eligible.

## Sessions, request cost, and caching

Every cache miss uses a fresh anonymous Banner session and carries Banner's
cookies only within that request. The semester inclusion flow normally makes
seven SDBOR requests. The instructor flow makes four when matches exist and
three when there are none. Browser-to-Worker traffic is still one request per
route per term.

Successful results are cached at the Worker for 15 minutes. Semester cache
entries are keyed by term. Instructor cache entries are keyed by term and a
lowercased, trimmed name. Error responses are not cached.

## Browser origins

The origin policy permits `https://rmwinslow.github.io`, HTTPS origins on
`rmwinslow.com` and its subdomains, and explicit localhost development
origins. It also permits the `null` origin used when the HTML page is opened
directly from a local `file://` path. The latter is acceptable because this API
contains only public course listings and no credentials or private data.

## Local commands

```text
npm install
npm run check
npm run dev
npm run deploy
```

`npm run check` performs a local Wrangler dry run. `npm run deploy` changes the
deployed Worker and must be run only when deployment is explicitly intended.
